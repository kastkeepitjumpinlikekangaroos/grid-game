# Grid Game - Multiplayer 2D Arena Game

A multiplayer 2D isometric arena game in Scala: 112 characters fight in lobby-based matches (free-for-all,
Teams, ranked) on a TLS-encrypted TCP + HMAC-signed UDP server built on Netty. The client draws matches
with LWJGL/OpenGL and its menus with JavaFX; all art and sound are generated by the Python scripts in
`scripts/`.

This file is the map. The detail lives next to the code it describes, in a `CLAUDE.md` in that
directory (Claude Code reads one when it works in its directory), and in the feature docs under
`design/` for what spans the server, the client and the model. **Before changing a module, read its
doc; before changing a feature, read its design doc** — each is listed in the index below.

## Build & Run

```bash
bazel build //...                                              # everything
bazel test //src/test/...                                      # every test (see src/test/CLAUDE.md)
bazel test //src/test/scala/com/gridgame/server:combat_test    # one test

bazel run //src/main/scala/com/gridgame/server:server          # the server (-- 25566 for another port)
bazel run //src/main/scala/com/gridgame/client:client          # the client (the login screen asks for host/port)
bazel run //src/main/scala/com/gridgame/mapeditor              # the map editor

OTEL_SDK_DISABLED=true bazel run //src/main/scala/com/gridgame/server:server  # server without telemetry
GRIDGAME_TELEMETRY=1 bazel run //src/main/scala/com/gridgame/client:client    # client with telemetry (or -- --telemetry)
bazel run //src/main/scala/com/gridgame/client:client -- --quality=low        # low|medium|high|auto (default auto; F7 in game)
GRIDGAME_AUDIO=off bazel run //src/main/scala/com/gridgame/client:client      # no sound at all
cd ops/observability && docker compose up -d                                  # Grafana at http://localhost:3000
```

## How the code is laid out

Every package is a Bazel library of its own and depends only on the packages above it in its list, so
work inside one package can't reach into another it doesn't declare (the BUILD file in each directory
names what it may use). The Maven jars are grouped in `third_party/jvm.bzl`.

```
src/main/scala/com/gridgame/
├── common/        shared by the server, the client and the tools
│   ├── (core)     Constants, WorldRegistry
│   ├── model/     the game's rules as data and plain logic: characters (roster/), projectiles,
│   │              effects, players, tiles, the world, barriers, traps, movement, teleports
│   ├── protocol/  the wire: 18 packet types, signing
│   ├── world/     WorldLoader (JSON maps)
│   └── observability/  the OpenTelemetry facade
├── server/        (common)
│   ├── net/       sockets, TLS, sessions, replay protection, rate limits, the Outbox
│   ├── account/   logins, profiles, the leaderboard (SQLite)
│   ├── game/      one running match: GameInstance, the requests players send it (ClientHandler),
│   │              projectiles, items, traps, validation
│   ├── bots/      the bots playing in a match
│   ├── lobby/     lobbies, the ranked queue, starting matches
│   └── (root)     GameServer, which puts them together, and ServerMain
├── client/        (common)
│   ├── gl/        OpenGL and GLFW primitives: batches, shaders, fonts, post-processing
│   ├── audio/, i18n/, net/   sound, the UI's text, the connection
│   ├── game/      GameClient: everything the client knows and does in a session
│   ├── render/    the renderer: core, then the painters (world/, hud/), then GLGameRenderer;
│   │              projectiles/ and blasts/ draw every projectile type and every explosion
│   ├── input/     keyboard, mouse, controller
│   ├── ui/        the menus' theme and widgets; ui/screens/ has a class per screen
│   ├── devtools/  the benches, the audit, the gallery, the golden frames
│   └── (root)     ClientMain (the JavaFX app) and MatchWindow (the match's GLFW window)
├── mapeditor/     the map editor (common)
└── tools/         the website's roster cards and the i18n content catalog (common)

src/test/scala/com/gridgame/   the tests, mirroring the source tree
scripts/     the Python asset generators and galleries, and the packaging scripts
worlds/      the maps (JSON)          sprites/  tiles and 112 character sheets
sounds/      generated audio          i18n/     the UI's text per language
design/      feature docs              plans/    work plans
docs/        the GitHub Pages website (not documentation of the code)
ops/observability/   the local OpenTelemetry → Prometheus/Tempo/Loki/Grafana stack
```

## Rules that hold everywhere

- **Judge a visual change by looking at it**, at the size the player sees it and over every ground:
  the projectile gallery, the sprite and tile galleries, the render audit, the ui gallery, a bench screenshot. A
  renderer change that is meant to change nothing is checked with the golden frames, pixel for pixel.
- **Measure performance rather than guess it**, with the render bench and the ui bench, running the
  two builds back to back: this machine drifts 20% between runs as it warms. The render thread
  allocates next to nothing per frame and must keep doing so (see client/CLAUDE.md).
- **When a test fixes a bug, check it fails with the bug put back.**
- **Every packet from a client is untrusted**: the server judges it against its own view of the match
  (PacketValidator) before taking any of it (see design/networking.md).
- A rule for how something works belongs in the doc beside the code it governs, or in its feature doc:
  when you change the behaviour, change the doc in the same edit.

## Bazel

`rules_scala` with Scala 2.13.16, Bazel 7.4.1. Dependencies: JavaFX 21.0.1, Netty 4.1.104, Gson 2.10.1,
SQLite JDBC 3.44.0, Guava 32.1.3, LWJGL 3.3.4 (glfw, opengl, stb + macOS ARM64 and Windows natives),
OpenTelemetry Java SDK 1.42.1 + autoconfigure + OTLP exporter + JVM runtime metrics (2.8.0-alpha). The
OpenTelemetry jars are exported by `common/observability`, so everything that depends on `//…/common`
has them. `server_lib` and `client_lib` are every library of each, for the tests.

JavaFX is a jar per platform (classes and natives), and a library only compiles against it (`JAVAFX`
is `neverlink`): a binary runs with the platform's jars it names itself (`MAC_NATIVES`,
`WINDOWS_NATIVES`, `JAVAFX_MAC`… in `third_party/jvm.bzl`), so a new binary on a JavaFX library must
name them, and `client_lib` has the build machine's (`HOST_NATIVES`) for the tests. That is what
keeps a Windows build made on a Mac to the Windows jars.

Build targets: `//src/main/scala/com/gridgame/server:server`, `//…/client:client`,
`//…/client:client_windows`, the dev tools in `//…/client` (`projectile_gallery`, `render_bench`,
`ui_bench`, `ui_gallery`, `render_audit`, `golden_frames`), `//src/main/scala/com/gridgame/mapeditor` and
`:mapeditor_windows`, `//docs:website`.
